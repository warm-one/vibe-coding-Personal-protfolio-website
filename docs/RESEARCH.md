# RESEARCH · 个人作品集网站

> 阶段一产物。这是一份非正式笔记，用来把「为什么做、别人怎么做的、我到底要什么」先想清楚。
> 使用者画像：走 vibe coding 路线的开发者；目的是**练手 + 未来展示**；核心板块已定：**项目作品展示 + 关于我**；技术栈交给后续阶段推荐。

---

## 一、目标

**要解决什么问题**

我现在没有一个属于自己的线上「门面」。做过的东西要么散在 GitHub 仓库里，要么只躺在本地，别人（未来的雇主、合作者、客户）想了解「我会做什么、做过什么、怎么联系我」，得自己拼凑。缺一个**一眼看明白**的地方。

**为什么值得做**

- vibe coding 这条路，别人看的是**结果**。作品集就是把结果摆到台面上的地方。
- **练手价值**：用真实项目，把前端工程化、设计、构建、部署整条链路亲手走一遍。
- **长期资产**：不是一次性作业。以后每做一个新项目就往里加一条，越攒越值钱。

**做出来是什么样（一句话愿景）**

一个**加载快、看着干净、手机上也好用**的站点：打开 3 秒内就知道「我是谁 + 我做过哪些项目 + 怎么联系我」，每个项目点进去有图有真相。

## 二、调研发现

### 市面上同类产品大致分三类

1. **平台托管型**——GitHub Pages、Vercel/Netlify 官方模板、Framer / Webflow 模板、Behance / Dribbble。
   - 优点：上手快，几乎零部署成本，模板开箱即用。
   - 缺点：**模板感重、容易和别人撞脸**；展示的是平台而不是「你」；深色定制和工程细节受限。
2. **框架手写型**——Next.js / Astro / Vite + React 的作品集站点。
   - 优点：完全可控、能顺带体现技术能力、SEO 与性能可优化到位。
   - 缺点：设计与内容都得自己扛，部署要自己配。
3. **现成作品集服务**——一堆「一键生成」的 SaaS。
   - 优点：快。
   - 缺点：被模板框死，长期扩展性差。**练手价值几乎为零**，与我们的第二个目的冲突。

### 2026 的设计趋势（可借鉴的）

- **极简 + 少即是多**：留白、清晰的层级、克制的动效，是当下的主流审美。
- **暗色模式逐渐成为默认**，而不是可选。
- **Bento grid（便当格布局）** 在个人主页上很流行，适合把「关于我 / 技能 / 项目」拼成一屏。
- **移动端优先**是底线，不再是加分项。
- 反直觉的趋势：**过度 3D / 满屏动效已经腻了**，堆特效反而显得不专业。

### 别人踩过的坑（我们要避开的）

- ❌ **首屏动效/预加载动画过重**：拖慢首屏，招聘方平均只停留 6–8 秒，来不及看清就关了。
- ❌ **项目堆太多、只有截图**：20 个平庸项目不如 5 个能打的项目；只有图没有「我做了什么、用了什么、结果如何」，等于没讲。
- ❌ **满屏技术名词**：重点被淹没，看不出价值和取舍。
- ❌ **移动端没适配**：字体太小、对比度低、横向溢出。
- ❌ **只有首页能看**：点进项目/详情是空页面或死链。
- ❌ **没有明确行动入口**：看完不知道下一步该干嘛（联系我 / 看简历 / 看 Demo）。

> 一句话总结：**别人拼的是「炫」，我要拼的是「清楚 + 快 + 能落地」。**

## 三、核心需求

1. **首屏 3 秒讲清「我是谁、我能做什么」**——姓名 + 一句话定位 + 主视觉，不要用预加载动画挡路。
2. **项目作品展示**——卡片形式呈现：封面图、标题、一句话简介、技术栈标签、GitHub / 在线 Demo 链接；可点开看单个项目的详情。
3. **关于我 / 个人简介**——头像、自我介绍、技能标签、（可选）经历时间线。
4. **联系入口随手可及**——邮箱、GitHub 等社交链接，页头和页脚都能找到。
5. **响应式 + 快**——移动端优先，图片懒加载，首屏轻量，动效克制。
6. **内容可维护**——新增/修改作品只需改一个数据文件或加一篇 Markdown，不动页面结构。

- [ ] 视觉风格倾向：**极简浅色** 还是 **暗色为主**？
