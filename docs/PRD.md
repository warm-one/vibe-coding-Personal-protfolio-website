# PRD · 个人作品集网站（精简版）

> 阶段二产物。输入来自 `docs/RESEARCH.md`。
> 原则：**保持精简**，不写八股。重点留三样——目标用户、MVP/后续的硬边界、字段级细节。
> 单人开发 · vibe coding 路线 · 技术栈由本文给出推荐。

---

## 1. 产品概述

一句话：**一个加载快、看着干净、手机上也好用的个人作品集站点**，让访客 3 秒内搞清「我是谁、我做过什么、怎么联系我」。

---

## 2. 目标用户

- **主要读者（访客）**：未来的雇主 / 面试官、潜在合作者或客户。特点是**停留短（6–8 秒）**、先看移动端、只看重点。
- **唯一开发者（我）**：走 vibe coding 路线的开发者。诉求是**练手**，以及一个**长期可维护、越攒越值钱**的门面。
- **给自己定的标准**：访客不需要思考「该看哪」，一眼扫过就知道我值不值得联系。

---

## 3. 核心功能

### 3.1 必须做（MVP）

> 每条都给到字段/交互级别，够直接开写。

**① 首页 Hero 区**
- 内容字段：姓名、一句话定位（tagline）、1–2 句自我介绍、主视觉（头像或纯排版大字）、两个 CTA 按钮「查看作品 / 联系我」。
- 交互：CTA 平滑滚动到对应区块；页面顶部导航（名字 + 锚点：首页 / 作品 / 关于 / 联系）。

**② 项目作品展示**
- 项目卡片字段：
  - `title` 标题
  - `summary` 一句话简介
  - `cover` 封面图
  - `tags` 技术栈标签（数组）
  - `links` GitHub / 在线 Demo 链接
  - `featured` 是否精选（可选，用于首页置顶）
  - `date` 日期（可选，用于排序）
- 卡片交互：hover 有**克制**的反馈（轻微位移/阴影，不做浮夸动效）；整卡可点进入详情。
- 项目详情页字段：`title`、`cover`、正文（Markdown：背景 / 我做了什么 / 结果）、`tags`、`links`、`gallery`（可选多图）、上一篇 / 下一篇导航。
- 数据来源：**一个 Markdown 文件 = 一个项目**。frontmatter 放结构化字段，正文写详情。新增项目只加文件，不动页面。

**③ 关于我**
- 字段：头像、自我介绍段落、技能标签、经历列表（可选：公司 / 时间 / 职位 / 一句话）、社交链接。

**④ 联系入口**
- 字段：邮箱（点击 mailto）、GitHub、（可选）其他社交。
- 交互：一键复制邮箱（可选）；**页头和页脚都能找到**。

**⑤ 全站基础设施**
- 响应式布局（mobile-first，先做手机再做桌面）。
- 浅色/暗色主题（MVP 先做一套，跟随系统可选）。
- SEO：每页 `title` / `description` / OG 图。
- 404 页面、favicon。

**MVP 明确不做**：博客、后台 CMS、数据库、多语言、评论、用户系统。

### 3.2 后续可以做

- 博客 / 技术文章（复用同一套内容机制）
- 简历 PDF 下载
- 项目按标签筛选 / 搜索
- 访问统计（Vercel Analytics 或 Umami）
- 手动主题切换按钮
- 联系表单（Formspree / Netlify Forms，无后端）
- 页面过渡动画（View Transitions）
- 多语言

## 4. 界面设计（按页面简述）

- **全局**：顶部导航（姓名 + 锚点链接，半透明/固定）；底部页脚（社交链接 + 版权）。
- **首页**：Hero（居中大字或左文右图）→ 精选项目网格 → 关于摘要 → 联系 CTA。
- **作品列表**：网格卡片，按日期倒序，精选置顶。
- **项目详情**：大图封面 → 标题 / 标签 / 链接 → Markdown 正文 → 上下篇导航 → 返回。
- **关于页**：头像 + 简介 + 技能标签 + 经历时间线 + 社交。
- **404**：一句友好文案 + 回首页按钮。

布局风格：**极简 + 留白**，暗色/浅色二选一先落地，避免满屏动效。

## 5. 技术栈建议

| 层 | 推荐 | 为什么 |
| --- | --- | --- |
| 前端框架 | **Astro** | 静态优先，默认几乎零 JS → **快 + SEO 好**，正合作品集场景；Content Collections 用 schema 管理项目，**新增作品 = 加一个 Markdown 文件**，直接满足可维护性需求。 |
| 样式 | **Tailwind CSS** | 上手快、AI 友好、样式一致，适合小团队/单人快速产出。 |
| 内容存储 | **Markdown 文件**（含 frontmatter） | 无数据库、版本可控、加作品零成本。 |
| 后端 | **无**（纯静态） | 作品集不需要服务端逻辑。联系方式用 mailto 或第三方表单服务。 |
| 部署 | **Vercel 或 Netlify**（免费额度） | 连 GitHub 自动部署、自带 HTTPS 与预览环境。 |

**备选：Next.js（React）**——如果你更想借这个项目**练 React 生态**，或未来要做更「应用化」的东西（带后端、复杂交互），选它。取舍：比 Astro 重、默认 JS 更多、纯内容站的收益不明显。
**Vue / Nuxt** 同样可行，但本项目内容驱动为主，Astro 是更省心的默认选择。

> 这一项将在 `/vibe-design` 阶段最终敲定，届时会问你一句。

## 6. 非功能性需求

- **性能**：Lighthouse 移动端各项 ≥ 90；首屏 JS 尽量少；图片用 WebP/AVIF + 懒加载 + 响应式尺寸。
- **可访问性**：语义化 HTML、对比度达标、键盘可导航、图片有 `alt`。
- **兼容性**：主流现代浏览器最近两个大版本（Chrome / Edge / Safari / Firefox）+ 移动端。
- **SEO**：语义化标签、sitemap、robots、OG meta。
- **可维护性**：组件化；新增项目只加一个 Markdown 文件。

---

## 7. 限制条件和边界场景（明确不做）

- ❌ 用户系统 / 登录
- ❌ 后台 CMS / 数据库
- ❌ 服务端动态逻辑（纯静态）
- ❌ 评论区
- ❌ 多语言（MVP 阶段）
- ❌ 花哨的预加载动画 / 全屏 3D（直接违背「快」的核心需求）
- ⚠️ 起步时若**还没有真实项目素材**：先用占位内容搭好结构，**不阻塞开发**，素材后续再替换。
